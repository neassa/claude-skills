## 2. How a page is assembled

1. **Action → PB forward.** After the action runs, `ActionController.pbRender` (`literatum/src/java/com/atypon/literatum/action/ActionController.java:725-741`) looks the JSP page path up as `frontend/page-builder-2/pages/<escaped path>` (`PAGE_CONTEXT_PATH`, `:124`). If a `PageContextConf` is defined it stores it as request attribute `pageContextConf` and forwards to `/pb2/renderPage.jsp` (PB3: `/pb3/renderPage.jsp`). Mobile UI and pages without a `<page>` entry keep the legacy JSP.
2. **Page definitions** are registry entries `frontend/page-builder-2/pages` = `<page name="/uri.jsp" pageGroup="…" pageType="…" subPage="…" shortcut="true"/>` (example `midtier.props.pb2.ux3.xml:21-28`; reader `PbPagesShortcutsLitImpl.java:40`). `renderPage.jsp` (`product/templates/jsp/pb2/renderPage.jsp:3-4`) turns it into `<pb:render-page pageType pageGroup pageSubType>`. Error pages are PB pages too: `404.jsp:3` → `pageType="404" pageGroup="Error"`, `500.jsp:4` → `pageType="500" pageGroup="Error"` (so a broken PB layer also breaks the error pages). Unknown URIs go through `Error404ProcessorPb2Impl` (`bridge/src/java/com/atypon/frontend/services/impl/Error404ProcessorPb2Impl.java:137-149`): editors are forwarded to `/pb/page<uri>`, everyone else gets the 404 page context.
3. **Context dimensions** (`page-builder-2.xml:367-583`): Website (`wgroup`, `website`), Page (`pageGroup`, `page`, `subPage`, `customPage`), Content Type (`ctype`, `csubtype`, filled from `pubType` via `frontend/page-builder-2/pubType/*`, `literatum.props.xml:11063-11075`), Publication (`category`, `journal`, `bookSet`, `issue`, `article`, `story`, `collection`), Topic. `LiteratumPopulateContext`/`PassportPopulateContext` fill them from the `ActionContext`. Custom pages (`PB_CUSTOM_PAGE*` tables) are matched by URI (`LiteratumCustomPageSelector`, `PbNormalizer` = `frontend/page-builder-2/normalizer`, `literatum.props.xml:10973`).
4. **Compile + render (pb2-core).** `PageRendererImpl.renderPage` → `PageCompilerImpl` builds the page from the scope tree and approved revisions/changes (`PB_SCOPE`, `PB_SCOPE_REVISION_REL`, `PB_REVISION`, `PB_REVISION_TO_CHANGE`, `PB_CHANGE*`); log strings: `Compile page from scopes`, `Find affecting scopes`, `Apply loaded changes for`, `Parent widget not found:`, `Failed to apply a change #%s`, `PageBuilder not bootstrapped`, `Clearing Page caches`. Then per widget: `Invoke widget controller`, `Render widget body using view`, `Widget returned empty result`, `Rendering of widget {} is disabled`, `Widget not found: {}`, `Page has no widgets`, `Failed to compile CSS` (all from 7.0.114 bytecode).
5. **Widget definitions.** `<pb:define-widget id label renderer-ref="…" view="ux3:<component>#<template>" controller-ref/controller-class>` with `<pb:properties>` forms and `<pb:meta><pb:property name value/></pb:meta>` (e.g. `ux3-widgets.xml:820`, `:910-929`, `:1157-1172`). Renderers wired in `page-builder-2.xml`: `pageBuilderJadeRenderer` (`:989-993`, a `JadeRendererFactory` that returns `pageBuilderNodeJadeRenderer` when `frontend/nodejs/enabled` else `pageBuilderJavaJadeRenderer`), `graphqlJadeRenderer` (`:995-997`, delegates ux3 views to the factory, `.jsp` to the JSP renderer, `asset:/…hbs` to handlebars — `GraphQLJadeRenderer.java:60-79`), `pageBuilderJspRenderer`, `pageBuilderHandlebarsRenderer` (`:1051`), `pageBuilderFreemarkerRenderer` (`:239`), `GaiaRenderer`, `pageBuilderNoRenderer`. Wrappers/decorations (`:101-164`) render through JSP. View resolution for `ux3:` views: `Ux3Utils.resolveView` (`literatum/src/java/com/atypon/modules/ux3/Ux3Utils.java:144-177`) — the editor's `ux3/template` widget property may override only the *default* view's template (`getMainViewAltTemplate`, `:126-142`, strips `-tmpl.jade`).
6. **Java fallback renderer** (`frontend/nodejs/enabled=false`): `JavaJadeUX3Renderer` + `Ux3ViewLoader` load `WEB-INF/products/<product>/{atoms,components,widgets}/<c>/templates/<c>/<t>-tmpl.jade` from the **local webapp** (`Ux3Utils.getTemplateFileName`, `:32-92`; product from `PRODUCT_NAME` env). Deployed envs do not ship the styleguide inside the war any more (`LiteratumViewLoader.java:56-61` calls this "legacy"), so with the renderer disabled every UX3 widget fails to find its template.
7. **Output post-processing** (`LiteratumPageBuilder.buildPage`, `bridge/src/java/com/atypon/frontend/services/impl/LiteratumPageBuilder.java:46-93`): writer wrappers for relative-href rewriting, **`DefaultResourceUrlRewriter`** (asset fingerprinting, §4.3), TeX detection; before the body it pushes `/early-hints` Link headers from the renderer (`pushUx3Headers`, `:133-137`) and `frontend/additionalFirstRequestHeaders` (`midtier.props.pb2.ux3.xml:60-65`, `<wro:product.css>` expanded via `WroUtil`).
8. **Startup work of this layer** (all on the web JVM, all DB-bound): `PageBuilderBootstrapper` (pb2-core; `The system looks like bootstrapped already. Doing nothing.` / `Bootstrapped Root Revision initial changes`), `Pb2CacheWarmup` on `CacheWarmupEvent` (`bridge/src/java/com/atypon/frontend/services/impl/cache/Pb2CacheWarmup.java:37-83`; keys `frontend/page-builder-2/cacheWarmup/{enabled,loadScopes,loadLatestRevisions,loadLatestRevisionsContent,loadAssets,loadPages}`, `page-builder-2.xml:16-23`; log `Loading page builder data` stopwatch table via `PageBuilderCachePrimingServiceImpl.prime{Scopes,LatestRevisions,LatestChanges,Assets,CustomPages}`), backstage-only crons `pageBuilderAssetsAutoCleaner`, `pageBuilderEmptyScopesRemover` (`${isBackstageServer}`, `page-builder-2.xml:830-834`, `:1002-1005`).

### 2.1 Liquibase-managed PB tables (PAGE_REMOVED / DROPZONE_ORDER)
- Schema owner: `changelogs/pb2-changelog.xml` inside `pb2-core-<v>-liquibase.jar`. In 7.0.114 it has 65 changeSets (last: `PB-LIT-443384`, `PB_CHANGE.VERSION`, `PB_RELATIVE_MOVES`, `PB_REV_CHANGES_INDEX_UPDATES`, `PB_CHANGE_CLEANUP`, `PB_REV_BASE_ID`) over tables `PB_SCOPE`, `PB_SCOPE_REVISION_REL`, `PB_REVISION`, `PB_REVISION_TO_CHANGE`, `PB_REVISION_CHANGES`, `PB_CHANGE`, `PB_CHANGE_{INSERT,REMOVE,MOVE}_WIDGET`, `PB_CHANGE_SET_WIDGET_PROPERTY`, `PB_ASSET`, `PB_CUSTOM_PAGE(_PROPERTY)`, `PB_SCHEDULED_APPROVAL`, `PB_FAVORITE_SCOPE`, `PB_RESTORE_POINT(_REV)`, `PB_REVISION_URL`, expression tables. **`PAGE_REMOVED` and `DROPZONE_ORDER` do not exist in 7.0.114** — they are columns added by 8.x changeSets.
- **Who applies it in Atypon envs: DB patches, not the webapp.** The full `updateDatabaseToTheLatestState()` bean `PageBuilderEnsureUpToDateDatabase` (`bridge/src/java/com/atypon/frontend/pagebuilder/service/impl/PageBuilderEnsureUpToDateDatabase.java:12-14`) is wired **only** in `spring/pb2/embedded-database.xml:41` (the HSQLDB dev profile). Production schema changes run one changeSet at a time: patch SQL directive `--$pagebuilderConfig(liquibasePatch,<changeSetId>)` → `PagebuilderConfigPatch.liquibasePatch` → `PageBuilderDatabaseUpdater.runChangeset(id)` (`bridge/src/java/com/atypon/bridge/patch/PagebuilderConfigPatch.java:235-236`, `:333-339`; pb2-core log `PageBuilderUpdateDatabase: Updating database by running changeset {} from changelog {}`). `DROPZONE_ORDER` = `lit31595.sql:8` (`PB_ADD_DROPZONE_ORDER`, with `PB_MIGRATE_INSERTS_INTO_MOVES`, `PB_MOVE_ADD_IMPLICIT`), `PAGE_REMOVED` = `lit31745.sql:6` (`PB-LIT-574805`) in `$LIT_REPOS/literatum-patch/mssql/literatum/`. Both carry a `--@boolean_property_parm="fr***"` gate (value masked; note 04 §3.3 — skipped where the property is false) and `--@release_parm='2610'`.
- Consequence: a **2610 war + a DB whose patch level predates lit31595/lit31745** fails at the first JPA query on those entities with Hibernate `SQLGrammarException: could not extract ResultSet` / `Invalid column name 'PAGE_REMOVED'` / `'DROPZONE_ORDER'` (note 14 #17, LIT-666058/LIT-678414). Depending on where it hits, it is a startup failure (cache warmup/bootstrapper → HostWaitForWebServer never passes) or a per-page 500. Read-only check: the DB `db_version`/patch table vs `lit31595`, `lit31745`; the two SQL files' gate property for the product.

## 4. Caches in this layer and how they are (not) invalidated

### 4.1 `ux3OutputCache` (rendered widget HTML) — `NodeJsJadeRenderer` (`bridge/src/java/com/atypon/frontend/pagebuilder/extensions/impl/jade/NodeJsJadeRenderer.java`)
- Config: LOCAL, 10000 entries, LFU, **no TTL** (`page-builder-2.xml:947-956`); created in `afterPropertiesSet` (`:471`). Master switch `frontend/nodejs/ux3CachingEnabled` (`:472`, base true `literatum.props.xml:12070`).
- Used when the render context says `cache=true`, or when caching is enabled **and** the widget definition carries the cache meta property (name masked by the viewer, `:231`) **and** the request is not "show pending edits", has no `?ux3Cache=false` or `?showJson`, and (non-prod) no `pug_address` cookie (`:119-120`, `:217-232`, `Ux3ServiceImpl.java:321-331`).
- **Key** (`:122-128`) = MD5/Base64 of `widgetSvc.computeWidgetCacheKey(widget, true) + "/" + frontend/nodejs/product-name` + view key (`view` + sorted string context entries except `cache`, `:188-203`). **The styleguide version is not part of the key.** Value = `CachedWidgetOutput(html, widget.lastModified)`; a hit is served only if `widget.getLastModified()` equals the cached one and the widget has no runtime-expression/i18n/`{{`/`${`/`<script` properties (`:129-139`, `:234-259`).
- Invalidation: none by event (no `StyleguideDeployedEvent` listener, nothing on `/invalidateCaches`), only LFU eviction, a widget edit (new `lastModified`) or a JVM restart. After a **styleguide-only** deploy the cached widgets keep the old markup until then; `?ux3Cache=false` bypasses per request.
- Async rendering (`frontend/nodejs/ux3AsyncRenderingEnabled`, `ux3AsyncRenderingMinDropzoneWidgets`=5, thread count `frontend/nodejs/ux3AsyncRenderingThreads` default 8, `:472-483`): child widgets of a dropzone with ≥5 widgets are rendered in a fixed pool and the dropzone HTML gets the placeholder `<!-- pb/async #<widgetId>/<view> -->` (`:101-103`). `finalizeTask` replaces it; on any exception it logs `Failed to render widget async: <id>` and **leaves the placeholder comment in the page** (`:389-412`) — the literal `pb/async #` in page source is the signature of a silently missing widget. `?ux3AsyncRender=false` disables it per request (`:418-420`); widgets with `cachingEnabled` or the async-disabling meta property up the tree render sync (`:425-466`).

### 4.3 Styleguide asset fingerprints (the "old CSS" path)
- `StyleguideManifestCacheServiceImpl` (`literatum/src/java/com/atypon/modules/ux3/impl/StyleguideManifestCacheServiceImpl.java`) is active only when `websiteAdmin/frontend/resourceUrlRewrite/replaceStyleGuideAssets` (`literatum.props.xml:25588`, true) **and** `frontend/HttpCacheFilter/styleguideProxyEnabled` (`:7845`, true) (`:34-38`). It fetches `/?p=&v=&r=/manifest.json` (`:59-71`); on non-200 → `Request to styleGuide failed with status code <n>` inside `Error requesting styleGuide manifest` (`:66`, `:75`), on a non-map body `Error manifest type is different from the expected type` (`:73`). **It is not loaded at startup**: the first `getManifest()` with an empty map triggers a fetch, then retries only every 30 min while empty (`:50-56`); once filled it is refreshed **only** by `StyleguideDeployedEvent` (`StyleguideDeployedListener.java:30`, which also deletes `<siteRoot>/releasedAssets`, `:32-41`). The Deploy Server never fires that event (note 12 §4.3) → after a styleguide deploy the JVM keeps the **old manifest until restart**.
- `DefaultResourceUrlRewriter` (`bridge/src/java/com/atypon/frontend/services/impl/DefaultResourceUrlRewriter.java:61`, `:92`, `:342-357`) rewrites every `…/releasedAssets/<name>` in page output to `manifest.get(<name>)` (the hashed file name) when present; `StyleguideAssetsFingerprintFilter` (`bridge/…/WidgetPropertyFilters/StyleguideAssetsFingerprintFilter.java:8`) first strips `-<20 hex>` fingerprints from widget property values so stored HTML widgets are re-fingerprinted. With a stale manifest the page references the **previous build's hashed names**; the renderer node no longer has those files after `rsync --delete-after` (note 07) → 404 from `HttpCacheFilter` (status copied, `Cache-Control: no-store`, `HttpCacheFilter.java:213-216`) → unstyled page / broken fonts, while an unfingerprinted request would have worked. With an **empty** manifest names stay unfingerprinted and the renderer resolves them via its own manifest (note 08) — works, but without long-term caching. (Renderer-side matching of stale hashed names: Unverified.)
- Fonts/SVG: `frontend/nodejs/extensionsToForceCacheControl` (`literatum.props.xml:12073`, `otf,ttf,svg,eot,woff,woff2`) makes the proxy override the renderer's `Cache-Control` with `frontend/HttpCacheFilter/CacheControl` (`public, max-age=31536000`, `:7844`; `HttpCacheFilter.java:194-212`) — a wrong font served once is cached by browsers/CDN for a year.
