## 1. Content model in one page

| Concept | Where | What matters for delivery |
|---|---|---|
| Publication hierarchy | `publish/src/java/com/atypon/publish/acs/metadata/` — `Publication` → `Journal → Issue → Article`, `Book → Chapter`, `DigitalObjectPublication` (docs/08) | Every content row carries a **`PATH`** (folder relative to the type root) and an **`AREA`** (`ContentArea`: live/staging/embargoed/… bits). `AbstractPublicationContent.save()` refuses `Path can not be null` when the area is a filesystem area and the item has disk content (`AbstractPublicationContent.java:1713-1714`). |
| DOI lookup | `PublicationCache.findByDoiArea(doi, WebArea)` (`publish/.../acs/metadata/PublicationCache.java:198-222`) | Returns **null** (not an exception) when no row covers the requested web area; several rows with one DOI are resolved in backstage-area priority order. |
| Not-found chain | `PublicationContentAction.findPublicationContent` (`publish/.../action/content/PublicationContentAction.java:441-469`) | `PublicationNotFoundException` / `PublicationContentNotAvailableException` (website filter) / `PublicationFormatNotAvailable` all extend **`AcsNotFoundException`**, which `ActionController` logs only as **WARN with the message** (`literatum/.../action/ActionController.java:624-627`) and turns into the 404 page (`PageKeys.PAGE_404`, `PublicationContentAction.java:143-145`). | Digital Objects | `publish/digitalobject` (runtime) / `publish/doeditor` (authoring); `PublicationAgentType.DIGITAL_OBJECT_PUB*` → `ContentDirDigitalObjects` (`AbstractContentDir.java:148-150`) | Stored as METS XML under `content/dobj-root`; DO folder = `<uri>/<encoded-doi>/<date-version>` (`SYGIDateVersionPathFactory.java:52-58`). |
| Aux files (PDF, suppl, media, figures) | `AuxFile` (`publish/.../backstage/auxiliary/AuxFile.java`) parses `<item>.aux.xml`; `AuxInfo.getLocationFile()` = `<dir of aux.xml>/<location>` (`AuxInfo.java:423-428`) | `AuxFile.loadIAux` is used by `deliverContent` (`DeliverContent.java:37-43`). Points for triage:
- The normalizer only maps URL → service name + params. **Whether the DOI exists is decided later** by `PublicationCache.findByDoiArea` (§1), so a DOI typo and a missing DB row look identical from the outside (404 page, WARN log).

- Item paths: `<content-root>/<jcode>/<year>/<group-doi-normalized>/<item-doi-normalized>/<yyyyMMdd[-NN]>/` (`SYGIDateVersionPathFactory.java:30-50`; `FileUtil.normalizeDoiSuffix`). ### 3.2 Startup check and direct file serving
- `server/verification-directory` = `${content/journal-root}` and `server/<type>/verify-file-system=true` for every role (`literatum.props.xml:26021,26031-26151`) → `Failed to verify file system for directory <dir>` → KILLING THE SYSTEM (note 12 §2.1). Only the **journal root** is checked; a missing `books`/`dos` mount is found per request.
- `FileServlet` (`literatum/src/java/com/atypon/modules/servlet/FileServlet.java`, mapped on `/`, `web.props.xml:65,68`) is the `com.atypon.tawseel` `FileDeliveryService`. Its `LiteratumPathResolver` (`:85-117`) serves **absolute publisher paths**: a request path that starts with `macro/publisher-home` is served from disk if the extension is in the allow-list (`gif,png,jpeg,jpg,sid,ppt,html,class,flv,apng,webp,svg`, `fp.png_v03`, `jpeg_v03`, …) or the request carries `CONTENT_DELIVERY_ACCESS_CHECKED` (set by the PDF transporter before `forwardPage`, `DirectRestrictedArticleTransporter.java:212-213`). Everything else resolves under the site root. This is why `/na101/`, `/na101v1/`, `/na102/` are in `robots.txt` disallow (`literatum.props.xml:12370-12372`): **figure and image URLs on legacy pages are literal NFS paths.** A missing or stale mount shows as image 404s with no Literatum log line (tawseel logs at DEBUG only, `FileServlet.java:63`).

### 4.1 Gaia `table_index`: what gets a new table, and when old ones are dropped
- **Cache key** for one render = `LiteratumTransformationSource.getCacheKey()` = the components of the publication's DB `PATH` (`literatum/.../gaia/LiteratumTransformationSource.java:44-55`; if `PATH` is null it logs `Publication <id> has no path defined in DB. Using default Gaia cache key strategy.` — WARN, Frontend logger) **plus** the template key `[templateId, scope-parts…, templateTimestamp]` (`LiteratumTransformationTemplateLocator.java:50-68`, the LIT-494688 hack). Templates come from the Gaia service over HTTP (`HttpTransformationTemplateLocator` / `CachedHttpTransformationTemplateLocator`, window `gaia/transformation-template-metadata-cache-window` minutes, `GaiaFeBeans.java:86-93`), so the **timestamp is the deployed Gaia bundle's template timestamp**.
- **New table** (note 05 §C3.2): the first render of a (template, scope, timestamp) triple in a JVM does `SELECT name FROM table_index WHERE id='<template>_<scope>_<timestamp>'`; on a miss it creates `<template>_<scope>_<random10>` and inserts the row. So a new table appears for every **Gaia bundle deploy** (`DC/deployconf.staging.xml:2822 <gaia bundle_version=… previous_bundle_version=…>`), for every new **`gaia/scope`** (= product) and never merely because Literatum was redeployed. The prepared statements are cached per JVM for life.
- **Stale lookup**: on a miss in the current table the cache consults up to `gaia/number-of-stale-cache-tables-for-look-up` (2) older tables (`midtier.props.gaia-fe.xml:34`), listing `table_index` once per hour; errors there are logged `[!] Error in Retrieving Stale Cache Version for …` and swallowed.
- **Drop**: `AC/gaia_cleanup.yml` (must be run with `label == 'cluster'`, on the first host of the group, `:16-37`) → `roles/cleanup/tasks/get_keyspaces.yml` selects **every keyspace whose name contains `gaia`** (`:4-6`) → `cleaner.yml`: reads `table_index`, groups ids by `sed 's/_\([0-9]\)[0-9]*$/_\1/'` (template + first digit of the timestamp, `:22`), keeps the **2 lexicographically newest** ids per group (`sort -r | tail -n+3`, `:37`), then `DROP TABLE IF EXISTS` (`:67-76`) **before** `DELETE FROM table_index` (`:78-85`), then `rm -rf` of data dirs by **prefix glob across all keyspaces** (`:88-96`) and `nodetool cleanup`. No cron or schedule exists in the ansible-cassandra repo; how it is triggered is outside these clones (Unverified).
- Consequences: a long-lived JVM serving an old bundle's template keeps its dropped table name → `InvalidQueryException: unconfigured table …` until restart; a JVM started between DROP and DELETE prepares against a dropped table on first render (note 05 §C4, LIT-682047). Because keyspaces are selected by substring `gaia`, a VOS or frontend-HTML keyspace is never touched by the CQL steps, but the `find … -iname '<table>*' -exec rm -rf` step can hit data dirs of other keyspaces with the same table-name prefix (note 03 §open item 2).

### 4.3 VOS: what can and cannot be said
- Deploy Server actions `CassandraRestoreVos`/`CassandraBackupVos`/`CassandraProductBackup` wrap `ansible-actions -s cassandra … -e keyspace_prefix=vos` (note 01 table, note 22 §CassandraProductBackup). The ansible restore does **`drop keyspace if exists`**, sleeps 10 s, then `putSnapshot` (schema replay + `sstableloader`), failing on `ERROR|Exception|Connection error` or a missing `Import operation complete` (note 03 §restore). A restore that fails after the drop leaves **no VOS keyspace**; a restore from an older backup leaves an **older VOS**.
- The keyspace holds Passport CMS objects (publication revisions, PB page data for pcms products). Which pages fail, and with which text, when the keyspace is absent or stale is **Unverified** here (library code). Observable proxies from this tree: pcms products are those whose props include `midtier.props.pcms.xml` (`passport/enabled=true`, `:71`) and their frontend reads publications through `BridgePubMeta`/`bridgeMappingSvc.findPublicationForRevisionAndWebArea` (`XsltServiceImpl.java:1200-1206`); a null there makes `makeCacheId` return null (`:1211-1215`) and `getInterface…` log `… No cached interface found.` / `… == null` (`:933,938`).
- **Next read-only checks:** `docker exec <cassandra> cqlsh -e "DESCRIBE KEYSPACES"` on the product's cluster (expect `vos_<product>_1820_<mode>_…`, `gaia_<product>_<mode>`, and for fe-cache products `<product>_<mode>_frontend_html`); `SELECT * FROM <gaia ks>.table_index;` and `DESCRIBE TABLES` in the same keyspace to spot index rows without tables; the last `CassandraRestoreVos`/`CassandraProductBackup` DS logs for `Import operation complete`.

## 6. PDF and binary delivery

1. `ShowPdf.displayPublication` (`publish/.../action/content/ShowPdf.java:35-80`): after ACS, `TransportAgent.find(serviceName, licenseId, userId)` loads the **transport agent from the DB** (`literatum/.../acs/transportagent/TransportAgent.java:58,100-112,151`: `Unable to load Transport Agent of type <id>`, `The service <s> is not supported by this Transport Agent.`, `Error in loading from <table> for Transport Agent <id>`). Web crawlers always get `DirectRestrictedArticleTransporter(true)` (`ShowPdf.java:85`). No agent → `Request could not be delivered, cannot find transport agent for service: <s>` + `ACSException("Internal Error: unknown service")` (`:78-79`) — a **DB/config** condition, not content.
2. `DirectRestrictedArticleTransporter.deliverRestrictedArticle` (`publish/.../acs/transportagent/DirectRestrictedArticleTransporter.java:82-127`): sets `Pragma: ""` and `Cache-Control: <LIMITED_CACHE>` (`:147-151`, "browser may keep it for one hour but must revalidate"), `Content-Disposition: <inline|attachment>; filename=…` (`:100-102`; Android prefers attachment, `literatum.props.xml:11234-11237`), optional `Accept-Ranges` (`:129-144`), then `deliver(...)` → sets `CONTENT_DELIVERY_ACCESS_CHECKED` and **forwards to the file URI**, which `FileServlet` serves from the publisher path (`:212-213`, §3.2). `IOException`s are only **WARN**ed (`Log.warn(Log.LITERATUM, ioe.toString())`, `:121-122`) — a truncated/unreadable PDF looks like a successful request in the action log.
3. `RestrictedArticleTransporter.getResourceUri` (`:196-203`): if the aux resource URI is null or `fileExists()` fails → `AcsNotFoundException(<messages "pdf.missing">)` → WARN + 404 page; `fileExists` logs `The URI "<uri>" does not map to a file` (ACS logger) when the servlet context cannot map it (`:160-177`). ## 7. CDN / Cloudflare: what Literatum sets and what it cannot do

- **Cache headers on assets:** `HttpCacheFilter` (`$10000`, PB2 products, `product/midtier/conf/midtier.props.pb2.base.xml:537-557`) uses `frontend/HttpCacheFilter/*` (`literatum.props.xml:7839-7846`): `fingerprintPattern` `(?:/pb-assets|/pb/assets/raw|/sda|/do)/.+(-\d{10,13})\.…` (strips epoch-millis fingerprints), `statusCodes=200, 206, 301, 304`, `CacheControl=public, max-age=31536000`, `styleguideProxyEnabled=true`, plus the masked `cachePathsPattern` and `publicResourcesPattern` `^(/cloud-reader/dist/.*?\.[0-9a-fA-F]+\.[^.]+)|(/cms/.+/asset/.+)$` (`:7838`). Its `CachedResponse` wrapper swallows the app's `Pragma`/`Expires`/`Cache-Control` and, for the listed status codes, writes the aggressive value; for other statuses it restores the originals (`literatum/.../servlet/HttpCacheFilter.java:324-386`); proxied styleguide assets with status ≥ 400 get `Cache-Control: no-store` (`:215`); fonts listed in the masked `frontend/nodejs/<extensionsToForceCacheControl>` (`otf,ttf,svg,eot,woff,woff2`, `literatum.props.xml:12073`) get forced caching (`:201-211`).
- Other header sources: CSL cache `public,max-age=3600,s-maxage=86400` (`:7733`), digital-feed `cache-control-header` / `cdn-cache-control-header` `public, max-age=86400, must-revalidate` (`:27731-27732`), 405 responses `Cache-Control: no-store` (`ActionController.java:614`), debug hooks `no-cache, no-store, must-revalidate`, PDFs `LIMITED_CACHE` (§6). Surrogate keys: `SurrogateKey` shortens hashes to `frontend/surrogate-key/size=7` (`literatum/.../util/SurrogateKey.java:15`, `literatum.props.xml:7937-7939`) — used for short URL/cache keys, **not** an HTTP `Surrogate-Key` header (no such header is set anywhere in `modules/servlet`, `literatum/action`, `literatum/frontend`).
- **Cloudflare in code = Stream + WAF tokens only.** `cdn/cloudflare/*` (`literatum.props.xml:12892-12935`; secret-bearing lines `:12912-12915`) drives video upload/transcoding (`bridge/.../workflow/CloudflareCdnProcessingProc`, `BridgeCloudflareServiceImpl` caption/audio-description upload, `CloudflareServiceUtil` signed playback tokens). HMAC/WAF-bypass secrets: `literatum.props.xml:6689-6690` (`ad…`, admin WAF bypass, LIT-418059) and `:7743,7747` (`frontend/hmac/*`, must match the Cloudflare WAF rule). **There is no Cloudflare cache-purge call in Literatum**, `CdnManager.purge` is unimplemented, and the Deploy Server's `CfInvalidateCache` step exits before purging (note 12 §4.3). After a deploy, Cloudflare keeps serving whatever it cached under the old `max-age`; the only purge path is outside these repos (Cloudflare dashboard/API by the CF owners).
- **What to check when "the page is stale after deploy":** response headers `CF-Cache-Status`, `Age`, `Cache-Control` on the URL; whether the URL is fingerprinted (new build → new fingerprint → miss) or not (PB pages, `/doi/…` HTML are not fingerprinted and should not carry the 1-year header unless a product `cachePathsPattern` matches them); `ux3OutputCache`/disk HTML cache on the JVM (§5) — restart clears the former, XSL mtime bump clears the latter.
