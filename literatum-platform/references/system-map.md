# Repo map — what each repo is and who talks to it

All under github.com/atypon. "Read" = read fully for this map (2026-09-25); details in `deep/`.

| Repo | What it is | Consumed by / talks to | Version/branch per env comes from | Read |
|---|---|---|---|---|
| **literatum** | Java 21 Gradle monolith (~34k Java files, 119 products). Gradle root `atypon/`; source roots `atypon/literatum` + `atypon/publish` compile together as `:literatum`; products `atypon/product/<p>` (thin layers over framework parents ux3/c3/acropolis/premium/metaPress). Config registry `*.props.xml`; Spring from registry `components/`. | Built by platform-tools `rebuild.py` on tools hosts → WAR → deployed by `redeploy.py`; patch VM run by `patch.py`. Depends on external libs pinned in `atypon/literatum/versions.properties` (cms-apis, gaia-registry/gaia-core, …) | deployconf `<product><source>…/literatum-worktrees/<BRANCH>/atypon` | deploy-relevant subsystems + docs (deep/04, 05) |
| **literatum-patch** | DB patch files per DB (`mssql/literatum/litNNNNN.sql` with `--@` headers) + Java stubs `com.atypon.patch.PatchNNNNNN` that `loadDynamicPatch` into literatum's `com.atypon.modules.migration.*`; `data/` fixtures | Symlinked as `$ATYPON_HOME/patch` by `sync_branches.sh`; packaged into the WAR (`iapps/patch`) used by the patch VM on DC hosts | plain `lit-NNNN`/`master` literatum → patch `master`; any other branch → same-named patch branch (must exist) | framework + samples (deep/04) |
| **ui-products** | Styleguide: one folder per product (+ groups), ux3 submodules; built with `utypon` (webpack); inherits `@atypon/amps`, `life-core`, `ui-base`, `ui-core`, `ui-article`, `ui-theme` | Built by platform-tools `Build-Deploy-Styleguide.sh` (ProductBuildStyleguide) → tarball → ansible-pugrenderer → pugrenderer nodes | deployconf `<styleguide><version>` (> `k8spugrenderer/@styleguide_branch` > default `products-integration`) | build path (deep/06 B) |
| **styleguide-render-pug** | NodeJS (NestJS) renderer: serves pug/ejs templates and static assets from `styleguide-templates/<branch>/ui-products/…`; in-memory caches with no TTL; `/invalidateCaches`, `/refreshProducts`, `/info` | Called by Literatum web (frontend nodejs address from deployconf pugrenderer cluster); image built by ansible-pugrenderer on cluster deploys | deployconf `<pugrenderer><cluster pugrenderer_version>` (V2.6.7 mostly; V2.4.0 rmit/aaas; stag amps asks for non-existent V2.7.0) | V2.6.7 full, V2.4.0 + 1.5.8 diffed (deep/08) |
| **deployconf** | One XML per account: products, families, hosts/processes, DB server names, and all service clusters (solr/zk, consumer/kafka, cassandra, redis, gaia, pugrenderer, elk…) with `deploy_version`s | Deploy Server (git-synced `main` every ~10 s), platform-tools (`setprod`/`deployconf.py`/`env.py`), ansible-inventory (`inventory.py`), XSL → `WEB-INF/deployconf.props.xml` inside each deployed webapp (becomes a Literatum registry layer) | itself (`main`); PR gate checks only well-formedness; XSD check post-merge always "passes" | full structure + 3 envs (deep/06) |
| **deployserver** | Java/GWT web app (Jetty) at deployserver.literatumonline.com; one Postgres table `deploy_action`; `config/actions.xml` command templates; SSH (typed shell) to hosts; decides pass/fail by text matching; no server-side auth | Operators/UI, githubbot (`/run`, `/hostStats`), cron templates; drives platform-tools + ansible over SSH; writes Jira/email | n/a | full, 434 files (deep/01) |
| **platform-tools** | Ops script repo, checked out as `~/scripts` on every host: `setprod`, `sync_branches.sh`, `rebuild.py`, `redeploy.py` (`rdply`), `restart.py` (`rstrt`), `patch.py`, `run_gradle.sh`, `Build-Deploy-Styleguide.sh`, `deployStyleguide.py` (no-op since 2026-02), DS cron scripts (15-day log cleanup, stuck monitor) | Invoked by the Deploy Server; reads deployconf; calls git/gradle/java/ansible | its own branch on hosts | deploy chain ~32k lines (deep/02) |
| **ansible-inventory** | `ansible-actions.py` wrapper + dynamic inventory from `~/.litconfig/deployconf.<account>.xml` | Every service deploy: `ansible-actions -s <svc> -p/-n … -a <playbook>` → clones `git@github.com:atypon/ansible-<svc>.git` at the version | service `deploy_version`, else product `lit_version` matched in the service repo's `atypon_lifecycle.json` (master) | full (deep/03) |
| **ansible-solr** | Solr cloud nodes + ZK bootstrap/collections; pauses/unpauses consumers | SolrDeploy/Stop/Backup/Restore | product `<solr deploy_version>` | full (deep/03) |
| **ansible-consumer** | Kafka→Solr indexing consumers (docker) | ProductConsumerDeploy | `<consumer deploy_version>` / lifecycle | full |
| **ansible-cassandra** | Cassandra clusters (docker); VOS keyspaces; **gaia_cleanup** drops old Gaia cache tables via `table_index` | CassandraDeploy/…, cleanup cron | cluster `deploy_version` (5.1.3) | full |
| **ansible-redis** | Redis clusters (docker) | RedisDeploy/Restart | cluster `deploy_version` | full |
| **ansible-gaia** | Gaia transformation service containers + bundles (Nexus/GAR) | GaiaDeploy (`-n <cluster>`) | gaia cluster `deploy_version` (2.0 = master) + product `<gaia bundle_version>` | full (deep/03 §5) |
| **ansible-pugrenderer** | Renderer containers; **delivers styleguide assets** (copy tarball from `~/warfiles`, rsync into `styleguide-templates/<branch>`, refresh, validate) | PugrendererProductDeploy / PugrendererInvalidateCache | pugrenderer cluster `deploy_version` (4.0/4.1) | 4.1 full, 4.0 diff (deep/07) |
| githubbot | Bot that queues Deploy Server actions | `/run`, `/hostStats` | — | plugin only |
| opstool, ansible-{zookeeper,kafka,elk,mssql,xse,atm,ingestion,searchservice,proxysolr,tools}, cms-root, gaia, id-core | lock/unlock/serverup, other services, external libs | see deploy-pipeline | — | **not read** |
